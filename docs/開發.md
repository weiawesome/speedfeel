# 開發

技術是 Vite、React、Tailwind、TypeScript。主要用手機寬度看。

## 日常

```bash
npm install
npm run dev
```

同一網路的手機要看，改用：

```bash
npm run dev -- --host 0.0.0.0
```

| 指令 | 做什麼 |
| --- | --- |
| `npm run dev` | 本地開頁 |
| `npm run lint` | oxlint |
| `npm test` | 跑模擬與 hook 的測試 |
| `npm run test:coverage` | 同上，並產生覆蓋率。範圍是 `src/sim` 和 `src/hooks` |
| `npm run build` | 型別檢查並建置 |
| `npm run preview` | 預覽建置結果 |
| `npm run a11y` | 對建置結果跑無障礙檢查。要先 `npm run build` |

第一次跑無障礙檢查前，安裝瀏覽器：

```bash
npx playwright install chromium
```

檢查會掃影片、短影音、三種動態版面，以及 `/why`，手機和桌面各一次。嚴重與重大的問題會讓指令失敗，完整結果在 `a11y-report/report.json`。

## 程式放在哪

| 位置 | 內容 |
| --- | --- |
| `src/sim` | 緩衝、畫質階梯、測速換算、說明文字、畫面繪製。這些是純函式 |
| `src/hooks` | 播放、動態的位元組管子、進站那一次測速 |
| `src/components` | 長片、短影音、動態，以及網速滑桿 |
| `src/App.tsx` | 三個畫面怎麼接在一起 |
| `src/Why.tsx` | `/why` |
| `scripts/a11y.mjs` | 無障礙檢查 |

1Mbps 等於每秒 125000 位元組。播放只跟著 Mbps 走；測到的第一包時間會寫在畫面上，不拿去拖延播放。模擬可以超過剛測到的速度，滑桿不是上限。

## 分支

`feat` 用 merge commit 進 `dev`，`dev` 再用 merge commit 進 `main`。提交留在歷史裡，不壓成一筆。

`dev` 是整合線。開向 `dev` 或 `main` 的 PR，以及推上這兩條線，會跑 `檢查-品質`（`.github/workflows/ci-check.yml`）：安裝、oxlint、測試、建置、無障礙檢查。

## 版本

`package.json` 的 `version` 是唯一的版本號。頁尾顯示的就是它，目前是 `1.0.0`。

要發版時，先改這個號碼，合併進 `main`。然後在這個 commit 打 tag，名稱必須是 `v` 加上同一個號碼，例如 `v1.0.0`。`發佈-Release`（`.github/workflows/release-tag.yml`）會核對 tag 和 `package.json`，通過後把建置檔掛到 GitHub Release，也上傳成 artifact。不上 npm。

## 部署

`部署-GitHub Page`（`.github/workflows/cd-pages.yml`）在兩種情況部署：`main` 的 `檢查-品質` 成功，或推上 `v*` tag。tag 必須和 `package.json` 的版本一樣，否則這次部署會停下來。站點路徑是 `/speedfeel/`。`/why` 重新整理要進得去，是因為建置時複製了一份和 `index.html` 相同的 `404.html`。`dev` 只跑 `檢查-品質`，不部署。

| 檔名 | 名稱 |
| --- | --- |
| `ci-check.yml` | `檢查-品質` |
| `cd-pages.yml` | `部署-GitHub Page` |
| `release-tag.yml` | `發佈-Release` |
